# 旅行规划Agent - Design Document

> TripBeam MVP｜PC 优先｜单日短时 30–240 分钟、出发点 8km 内。本文为前端实现规范：时间、距离、合规、风险等级与保存资格均以后端确定性 Planner 返回为准；Dify/LLM 仅进行意图提取、追问与基于已验证事实的文案生成。

## 1. 设计理念 & 差异化设计主张（重点，写出独特思路）

### 设计主张：把不确定的出发，变成可看见的取舍

TripBeam 不把旅行包装成“完美攻略”或目的地内容流，而是一张可快速比较、理解和修改的**城市决策桌**。临时到了陌生城市，用户缺少的不是更多景点，而是能在有限时间、体力与陌生感之间放心做取舍。

产品持续提供三类决策证据：

- **时间余量**：显示已用时间与可呼吸的缓冲分钟，不用进度条制造赶路感。
- **路线差异**：2–3 条方案平等并列，用路线指纹、差异矩阵、地图线型回答“它们差在哪”，而非算法宣布“最佳”。
- **空间关系**：地图是编辑画布，不是背景；选中的方案、停靠点、风险和清单同步联动。

这套体验称为 **「松弛的决策台（Relaxed Decision Desk）」**：克制但不冷硬，自然但不文旅化；AI 清楚说明已确认与待确认，最终控制权在用户。

| 常见旅游 App 范式 | TripBeam 的取舍 |
| --- | --- |
| 封面图、榜单、内容流激发“想去” | 路线指纹、时间余量、空间连贯性帮助“现在就决定” |
| 单一路线、算法替用户排序 | 同屏给出不同节奏且同样合规的方案，用户横向选择 |
| 地图用于导航或背景 | 地图与清单组成编辑器；点位是可操作节点 |
| AI 长文陪伴、泛泛推荐 | AI 只问缺失字段、解释已验证事实，不过度承诺 |
| 限制在最后提交时暴露 | 4 小时与 8km 以温和持续的约束脉冲呈现 |

**体验原则：**

1. 先回答“差在哪”，再要求“选哪个”。
2. 先保留随性，再提示边界；只有不可保存时才阻断。
3. 未知即“待确认”，不声称实时排队、即时营业或模型估算的数值。
4. 编辑即失效重算；拿到规则结果前不让旧指标伪装成新结论。
5. 自然质感来自暖雾白、苔绿、砂岩色、留白和轻边界，不来自明信片大图、装饰插画或高饱和渐变。

## 2. 目标用户与设计目标

| 用户 | 场景与焦虑 | 设计回应 |
| --- | --- | --- |
| 临时抵达的独行者 | 不熟路、时间碎、不想研究攻略 | 一句话输入 + 最多 3 项追问 + 立即可比路线 |
| 轻量结伴出行者 | 偏好不一致，难以快速达成共识 | 平权方案、差异矩阵、版本化分享快照 |
| 有体力/时间边界的游客 | 怕走太多、赶时间、踩营业空 | 步行强度、时间余量、风险与恢复操作常驻 |

- 对比页首屏识别主题、时长、距离、POI 数、步行强度、余量、理由和风险。
- 正常 complete 展示 2–3 条 valid 路线；degraded 只展示真实精简方案，不伪造多方案。
- 编辑后 2 秒内展示“校验中”和确定性结果；invalid_draft 不可保存或分享。
- 地图失败不阻断文字路线、编辑、保存和分享。
- 关键信息均有文字、数值或图标，不仅依赖颜色。

初次输入与追问回答都回到同一 Dify 意图节点。前端状态为 collecting_preferences、needs_user_input、generating、complete、degraded、recalculating、invalid_draft；UI 不得自行推断路线数量、距离、时长、风险等级、有效性或保存资格。

## 5. 视觉设计系统

### 5.1 风格关键词

**松弛、自然、可信、清醒、可比较、可操作。**

基调是“城市晨雾里的旅行桌面”：暖白像纸，苔绿承担行动，砂岩色提供温度，深墨绿保障扫读。地图低饱和、低对比，让路线色与编号优先。照片仅可作为 POI 详情的小辅助，不能占据首屏或主导路线选择。

- 字体栈：PingFang SC、Noto Sans SC、Inter、Microsoft YaHei、sans-serif。
- 数字启用 tabular-nums，保证时长、距离、矩阵列稳定。
- 不用手写体或旅游海报字，情绪由留白和色材表达。

### 5.4 图标、圆角、阴影、间距基础规范

| 项目 | 规范 |
| --- | --- |
| 图标 | 统一 1.75px 线性图标，默认 20px；状态不只靠颜色。地图点位使用编号圆点。 |
| 圆角 | 8px 标签/小控件；12px 输入、卡片；16px 大抽屉、地图。 |

## 6. 核心页面详细设计

### 6.1 首页｜需求输入页（初始输入）

**目标：**用户可由“下午想吃点当地菜，顺便拍照，不想太累”开始，而不是先填表。

PC 最大宽度 1200px：左侧 7 列是对话/输入，右侧 5 列是“此刻已听懂什么”的偏好摘要。顶栏仅有 Logo、位置入口、草稿状态，不放营销 Banner。

- 标题：今天这几小时，想怎么过？副文案：告诉我大概从哪出发、什么时候有空，剩下的可以一起想。
- ChatComposer 最少 3 行、最多 6 行；Enter 发送、Shift+Enter 换行。输入下只有三个文本示例：想吃点当地的、想散步拍照、不想赶路；点击只回填文本，不绕过 Agent。
- PreferenceSummaryPanel 分“已确认 / 待确认”显示起点、时间、时长、兴趣、行动方式；待确认空槽可进入对应问题。地点支持定位、搜索、手填、地图选点，拒绝定位不阻断。
- 发送后用户气泡立即落位，Agent 显示“正在理解你的出发条件”，摘要逐字段骨架填充。解析时可改输入但禁重复提交；新请求取消旧 loading 的视觉归属。

### 6.2 追问补充页｜偏好澄清交互

**目标：**把缺失字段变成低认知补充，而不是问卷。页面承接原对话，每轮最多 3 张卡；顺序为出发点 → 时间/时长 → 兴趣/行动方式。

| 字段 | 组件与规则 | UI 细节 |
| --- | --- | --- |
| origin | 地点搜索 + 地图选点 | 显示地点名和“更换”；前端不臆造坐标 |
| startTime / availableMinutes | 时间选择 + 30/60/90/120/180/240 分钟 | 大于 240 提示“最多 4 小时”，不可生成 |
| interestTags | 最多选择 3 项兴趣 | “随便走走”可映射 relax，但至少选一项 |
| mobility | 少走路 / 正常走走 / 可以搭车 | 文字优先，不暗示体力等级 |

- 选项采用 2–3 列可选卡，选中以浅绿底、边框、✓ 三重反馈。
- “稍后再说”仅限非必要字段；必填项解释原因，例如“为了把路线控制在你真正可用的时间里”。
- 回答先写入本地摘要，点击“继续规划”才合并回传；摘要可回改，回改后受影响回答标为待确认。
- LLM 异常统一为“我还需要确认几项出行偏好”，转同样的结构化卡，不暴露 JSON/模型错误。

### 6.3 方案对比页（最重要页面：多行程并排对比）

**目标：**无需进详情，用户已经能决定哪种“更适合此刻”。本页是横向决策面板，不是普通路线卡片列表。

**PC 结构**

1. DecisionHeader：返回修改偏好、起点/时段/时长摘要、重新生成。
2. RouteComparisonBoard：2 条等分两列，3 条等分三列；每列最小 320px、最大 420px、统一高度，禁止瀑布流。
3. 下半部左为差异矩阵，右为共享地图预览（约 5:7）；均由 selectedRouteId 驱动。
4. 固定底部操作区显示已选路线和“查看并编辑”；保存/分享只在选定有效路线后可用。

**RouteOptionCard 固定信息顺序**

1. 4px 色带、方案 A/B/C、主题名称；不用“最佳/首选”。
2. RouteFingerprint：3–5 个类别图标或站名缩写细线串联，超出显示 +N，让用户一眼识别 POI 组成和顺序。
3. 指标网格：总时长、总距离、步行强度；第二行 POI 数与**时间余量**（240 减总时长）。余量 <20 分钟只加警告图标，不改写数值。
4. 一句推荐理由，最多 2 行，且只来自后端已验证事实。
5. 最多 2 枚风险摘要，优先 warning/critical；其余收为“还有 N 项需要留意”。
6. “查看并编辑”主按钮；卡片空白点击只选中并联动地图，不跳转。

选中态使用路线色 2px 边框、淡色底和“已聚焦”文字标签；地图选中路线为实线，其他路线降至 35% 透明度。Hover 仅提升边框和阴影，不暗示推荐。卡片可 Tab 聚焦，Enter/Space 选中。

**RouteDifferenceMatrix**

矩阵只高亮差异，不重复堆叠卡片。行包括路线节奏、时间余量、空间跨度、步行强度、POI 组成、营业/时间风险、适合此刻；列头固定 A/B/C（色条+主题）。同值正常显示，差异项用淡底而不以红绿评判。数值格式统一为 3h 20m、2.8km、低；缺失写“待确认”。

少于 2 条路线时不渲染矩阵，改为“精简方案说明”：明确保留的硬约束、已放宽的软偏好，提供调整偏好、更换出发点、查看精简路线。

共享地图默认纳入全部路线，选中路线加粗。点击 POI 或 Polyline 选中路线并滚动到卡；卡片 hover 不触发地图。地图失败则替换为文字版空间摘要，卡片、矩阵与选择保持可用。

### 6.4 行程详情&地图编辑页

**目标：**让用户看着空间关系修改，同时一直明白修改的代价。

~~~text
┌──────────────────────────────────────────────────────────────────────┐
│ ← 返回对比 [方案A][方案B][方案C] 3h20m · 2.8km · 45m余量  保存 分享 │
├──────────────────────────────┬───────────────────────────────────────┤
│ 行程清单 360px                │ 地图画布（自适应）                   │
│ 起点 / 停靠点 / 路段          │ 编号点位、路线、图例、缩放、定位       │
│ 拖拽排序 / 删除 / 替换        │ 点击点位 ↔ 高亮列表项                 │
├──────────────────────────────┴───────────────────────────────────────┤
│ 约束脉冲条：状态 + 原因 + 可行动作                                    │
└──────────────────────────────────────────────────────────────────────┘
~~~

- RouteSwitcherTabs 保留色、字母、主题。切换只改变编辑上下文；未完成重算的草稿离开前提示“保留草稿 / 继续编辑”。
- ItineraryStopList 中起点固定首位；POI 显示编号、类别、停留时间、地址摘要、营业风险。相邻站间由独立 TravelSegment 显示方式、分钟、距离。
- ItineraryStopItem 提供拖拽把手、替换、删除、地图定位。删除二次确认；重排不确认，释放即重算。
- ReplacePoiDrawer 只展示规则侧返回的同类/附近候选，并标出已有的时间/距离增减；新增地点走同一候选抽屉，前端不可任意拼路线。
- 地图点位与列表编号一致。MVP 中地图点位**不能自由拖坐标**：拖拽手势提示“请在左侧调整停靠顺序”，防止未校验空间编辑；点击 POI 联动列表并开启快捷操作。
- 固定 ConstraintPulseBar：valid 写“路线仍留有 45 分钟余量”；recalculating 写“正在重新校验路线…”并禁用保存/分享；invalid_draft 写具体超出分钟/违反项，提供自动删减、替换附近地点、恢复上一合规版本。
- 地图不可用时右栏替换 MapFallbackPanel，保留顺序、地址、路段时间、距离和重试；编辑/保存/分享可继续（路线本身须 valid）。

### 6.5 分享页

分享是经验证行程的**不可变快照**，不是协作编辑文档。

- 仅 constraintStatus 为 valid 且非重算中可创建；点击先创建服务端快照，再显示分享面板。
- 首屏包含主题、出发条件、版本时间、时长/距离/余量、停靠点时间线、风险说明、地图或文字降级路线。
- 显著文案：这是行程 v{version} 的快照，后续修改不会影响此链接。
- 操作：复制链接、系统分享、复制文字行程；成功 Toast 保留链接。链接失效/撤销/网络失败给明确状态和本地草稿入口。
- 不展示内部评分、Dify/模型信息、精确位置来源；不支持评论或直接编辑。

## 7. 交互规则（对齐Agent状态）

### AI思考中loading状态

| 状态 | 页面表现 | 可用/禁用 |
| --- | --- | --- |
| collecting_preferences | Agent 三点呼吸与“正在理解你的出发条件”；摘要字段骨架 | 可编辑未提交输入，禁重复发送 |
| needs_user_input | 对话后插入结构化追问卡，明确还差什么 | 可回答、返回修改；不显示路线骨架 |
| generating | “收集附近选择 → 安排不同节奏 → 检查时间边界”依序展示 | 可改偏好；不可把旧方案当新结果操作 |
| recalculating | 受影响路线半透明并写“正在重新校验” | 可看草稿；禁保存、分享和依赖新指标的操作 |

超过 8 秒改为“还在核对路线，稍后可重试”；保留输入与偏好。所有 loading 必须有文本或骨架，不得整页白屏、虚构百分比。

### 追问交互规则

- 每轮最多 3 问，严格按规则侧 missingFields 决定，前端不凑数。
- origin、startTime、availableMinutes、至少一个 interestTag、mobility 未完成时，“继续规划”不可用，并给具体字段原因。
- 回改字段后受影响答案标为待确认；模型超时/非法输出进入结构化补问，保留原话。

### 方案切换、行程编辑、拖拽地图点位

- **方案切换：**对比页选择只更新 selectedRouteId 与地图焦点；点击查看并编辑才跳转。编辑页 Tab 切换不修改路线。
- **编辑命令：**删除、替换、重排只提交 baseVersion、操作类型、POI id/顺序；前端不得提交总时长、距离、风险或有效性结论。
- **拖拽排序：**仅可在停靠点间拖拽、不可越过起点；键盘支持 Space 拿起、方向键移动、Space 放下。释放后立即进入 recalculating。
- **地图点位：**点击联动列表；不开放自由拖点。未来若支持地图选点新增，必须先经地理编码和 Planner 候选校验。
- **版本冲突：**后端 baseVersion 冲突时提示“路线已有更新”，给“查看最新版本 / 复制当前草稿为新尝试”，绝不静默覆盖。

### 风险提示的展示样式

风险码与等级由后端给定，前端/AI 只能可读化，不能降级或隐藏。

| 风险 | 位置与文案 | 行动 |
| --- | --- | --- |
| OPENING_HOURS_UNCERTAIN / POI_DATA_PARTIAL | POI 行内 + 卡片摘要；信息/警告色 | 查看详情；提醒自行确认，不写“当前” |
| ROUTE_TIME_TIGHT | 指标旁 + 约束脉冲条，显示剩余分钟 | 删减/缩短停留 |
| PREFERENCE_RELAXED | 对比页顶部说明条，解释放宽的软偏好 | 调整偏好或接受 |
| ROUTE_COUNT_LIMITED | 取代矩阵的精简方案说明 | 调整偏好/起点或查看精简路线 |
| EDIT_EXCEEDS_LIMIT | 固定约束条，错误样式 | 自动删减/附近替换/恢复上版 |
| MAP_UNAVAILABLE | 仅地图容器信息态 | 重试地图 |

## 8. 异常 & 空状态设计

| 场景 | 视觉与内容 | 主操作 |
| --- | --- | --- |
| LLM 解析失败 | 对话内显示“我们需要确认几项出行偏好”，保留原输入 | 补充出发点、时间、偏好 |
| POI 不足 | 小型线性图标 + 说明硬约束未放宽，不用失落插画 | 调整偏好 / 更换出发点 / 接受精简方案 |
| 仅一条 degraded 路线 | 不伪造矩阵；卡片标“精简方案” | 回到偏好 / 查看路线 |
| 地图 SDK/瓦片失败 | 地图区域替换为顺序、地址、路段文字 | 重试地图 |
| 路径绘制失败 | 保留编号点与列表，说明暂无法画连线 | 重试地图 |
| 编辑超限 | 草稿可见，上一合规版可识别，显示具体超出 | 自动删减 / 替换 / 恢复 |
| 重算超时 | 保持 recalculating，不把旧结果说成新结果 | 重试 / 恢复上版 |
| 离线或保存失败 | “草稿已保留在本机”，分享禁用 | 重试保存 |
| 空草稿 | 一句引导 + 三个文本示例，无大插画 | 输入需求 |
| 未授权位置 | 搜索/手填/地图选点替代，不反复要权限 | 输入出发点 |

## 9. 响应式适配规则（PC优先，兼顾移动端）

| 范围 | 布局规则 |
| --- | --- |
| ≥1280px | 方案 2–3 列并排；矩阵/地图分栏；编辑器左栏 360px。 |
| 1024–1279px | 3 卡可横滑，首两张完整露出；矩阵横滑且首列固定；编辑栏 320px。 |
| 768–1023px | 摘要移到对话下；方案卡横向 snap（约 78vw）；编辑器地图上、清单下。 |
| <768px | 紧凑约束摘要 → 横滑方案卡 → “查看差异”底部抽屉 → 全宽地图；清单为 70% 高 Bottom Sheet，保存/分享固定底栏。 |

- 移动端不可把方案变成失去关联的纵向列表：保留横滑、A/B/C 标记、差异抽屉和地图联动。
- 横滑区提供渐隐边缘及“可横滑比较”提示，支持触摸、滚轮转横向和键盘导航。
- PC 使用右侧 Drawer/Popover，移动使用底部抽屉；危险操作确认逻辑一致。
- 地图最小高：PC 560px、平板 420px、移动 46vh。

## 10. 动效原则（克制、服务AI感知，不要花哨）

动效只解释“正在理解、比较、重算、已联动”，不抢数据注意力。

| 场景 | 动效 | 时长/缓动 |
| --- | --- | --- |
| AI 思考 | 三点低幅呼吸 + 文本 | 900ms 循环，ease-in-out |
| 偏好确认 | 字段骨架淡入，✓ 轻显 | 180ms，ease-out |
| 卡片选中→地图 | 色边/线条加深，地图平移到范围 | 180ms / 280ms，ease-out |
| 卡片 Hover | 边框与轻阴影 | 140ms；不位移卡片 |
| 拖拽排序 | 占位平滑让位，释放后出现校验条 | 160ms；无弹跳 |
| 风险升级 | 约束条由下方 8px 淡入 | 200ms；不闪烁、不震动 |
| 成功反馈 | Toast 淡入淡出 | 180ms；3 秒消失 |

- 遵循 prefers-reduced-motion: reduce：取消地图飞行、呼吸、列表位移动效，只保留即时状态。
- 不伪造加载进度；用户操作地图时不抢控制权。
- 禁止自动视频、粒子、漂浮贴纸、炫技路线绘制等装饰动画。

## 11. 设计评审验收清单

- [ ] 首屏没有内容流、目的地大图或“唯一最优”叙事；能感知“松弛的决策台”。
- [ ] 初次输入允许模糊表达；追问严格按缺失字段，每轮不超过 3 项。
- [ ] 出发点、开始时间、时长、至少一个兴趣、行动方式未完整时，不进入路线生成。
- [ ] 所有加载有可读状态或骨架，无白屏和虚假进度。
- [ ] 对比首屏并列展示主题、时长、距离、POI 数、步行强度、时间余量、理由、风险。
- [ ] 2–3 条路线视觉平权；不以排序、面积或强色暗示官方最优。
- [ ] A/B/C 通过色条、字母/主题、线型三重区分；不依赖颜色。
- [ ] 差异矩阵突出不同；一条 degraded 路线时不伪造比较。
- [ ] 卡片、矩阵、地图共享 selectedRouteId；地图失败不阻断核心流程。
- [ ] 编辑只发命令与版本号；时长、距离、风险、有效性均由后端重算。
- [ ] 编辑后旧指标标为失效；重算中禁保存/分享；invalid 草稿不可保存/分享。
- [ ] 风险同时有图标、文字、等级、行动，不声称实时排队或未验证营业。
- [ ] MAP_UNAVAILABLE 是地图降级，不等于路线不合规；文字路线完整可用。
- [ ] 分享为仅对 valid 路线开放的不可变版本快照。
- [ ] PC 至移动端均保留横向方案比较能力。
- [ ] 已覆盖颜色对比、键盘焦点、键盘拖拽替代、最小触达区与 reduced motion。
